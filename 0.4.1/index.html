    AI forecasting assistant, powered by skforecast

    The forecasting assistant that shows its work

    Give it a time series. skforecast-ai profiles the data, chooses the model with deterministic rules, validates it and returns the forecast together with the skforecast script that produced it. An optional LLM explains every decision; it never makes them.

        Design
        
    Deterministic first, LLM second
    
        
    Forecasting decisions come from rules you can read and reproduce. The language model sits on top: it explains them, and helps you change them when you ask.
    
        See it in motion →
      
    
      
    
        
    
          The engine decides
          
    Rule-based and reproducible
    
          
      
            
    • Forecaster and estimator from the shape and size of the data.
      • 
            
    • Lags and window features from the partial autocorrelation and the frequency.
      • 
            
    • Metric and cross-validation that match the scale of the series and the horizon.
      • 
            
    • Model ranking as a plain sort of backtesting metrics.
      • 
          
    
          
    No LLM needed. The same data always gives the same profile, plan, script and predictions.
    
        
    
        
    
          The LLM explains
          
    Optional, and always validated
    
          
      
            
    • Explains any profile, plan, script or result in plain language with ask().
      • 
            
    • Refines lags and window features on request with refine_plan().
      • 
            
    • Translates a deployment scenario into a backtesting strategy with create_cv().
      • 
            
    • Grounded in the skforecast agent skills, picked for each question.
      • 
          
    
          
    Its output is checked by a Pydantic model before it touches execution. Your dataset is never sent: profiles carry summary statistics, and a result passed to ask() only its own predictions and metrics, with a warning.

          Code
          
    The code you see is the code that ran
    
          
    forecast() and backtest() execute the same script that forecast_code() and backtest_code() return. No hidden steps, no lock-in.
    
        
    
        
      
          
    • Inspect it. Every decision of the plan is a line you can read.
      • 
          
    • Own it. It imports pandas, skforecast and your estimator. Nothing else.
      • 
          
    • Ship it. Version it, review it and run it in production.
      •

          Model selection
          
    Let measured performance pick the model
    
          
    compare() backtests every candidate with the same data and the same cross-validation, so the differences come from the models, not from the setup.
    
          See it in motion →
        
    
        
      
          
    • Your candidates or the alternatives proposed by the profile.
      • 
          
    • A ranked leaderboard with a seasonal naive baseline as the reference, and the reproducible code of every row.
      • 
          
    • The winner ready to forecast. The LLM plays no part in choosing it.
      • 
        
    
      
    
    
    
  
    

  
    
    
    
      
    
        
    
          LLM layer, optional
          
    Ask why, at any step
    
          
    ask() explains a result or a plan in plain language, or answers a general forecasting question, grounded in the skforecast agent skills. It reads the object you pass; it never runs the workflow or changes a parameter.
    
        
    
        
      
          
    • After the results. Forecasts, backtests and comparisons, with their metrics.
      • 
          
    • Before running anything. Question the plan: its lags, window features and interval.
      • 
          
    • Your dataset stays local. Only summary statistics and the values a result owns are sent.
      • 
        
    
      
    
      
    
    
    
    
      
    
        
    
          Refine the plan
          
    Your domain knowledge, as lags and window features
    
          
    plan = assistant.refine_plan(
    profile, plan,
    prompt="Demand peaks at rush hour and is "
           "similar to the same hour last week.",
)
    
          
    The LLM proposes the features, a Pydantic model validates them and the deterministic engine builds the plan. If the proposal is not valid, you get the deterministic plan and a warning.
    
          Refine the plan →
        
    
        
    
          Describe the deployment
          
    A scenario in plain words, as a backtesting strategy
    
          
    cv = assistant.create_cv(
    profile, plan,
    prompt="Train once on data up to August "
           "and forecast 36 hours ahead.",
)
    
          
    The answer becomes the parameters of a skforecast TimeSeriesFold, validated before the backtest runs. If they are not valid, the deterministic strategy is used, with a warning.

        Workflows
        
    One call, or every step in your hands
    
        
    The same engine behind four entry points. Each step returns an object you can inspect, change and pass on.
    
      
    
      
    
        
    
          Fast path
          
    From data to forecast in one call
    
          
    assistant = ForecastingAssistant()
result = assistant.forecast(
    data, target="y", steps=12
)
result.predictions
result.code
    
          Agentic forecasting →
        
    
        
    
          Step by step
          
    Review every decision
    
          
    profile = assistant.profile(
    data, target="y"
)
plan = assistant.plan(profile, steps=12)
cv = assistant.create_cv(profile, plan)
result = assistant.backtest(
    data, cv, profile=profile, plan=plan
)

          Terminal

    --target y --steps 12

$ skforecast-ai forecast-code data.csv \
    --target y --steps 12 \
    --output forecast.py
