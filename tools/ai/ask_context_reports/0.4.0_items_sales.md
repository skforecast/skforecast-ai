### [grounded] For hourly demand with strong daily and weekly seasonality, when should I prefer a direct forecasting strategy over a recursive one?

- Skills: choosing-a-forecaster; 8.2s

You should prefer a direct forecasting strategy (`ForecasterDirect`) over a recursive one when the predictive relationship changes significantly across the forecast horizon or when recursive error propagation degrades long-term forecasts. In hourly demand applications, direct forecasting trains an independent estimator for each lead time, ensuring that errors from earlier predictions do not compound into later hours. However, this comes at the expense of training multiple models and requiring a fixed horizon defined at initialization.

## When to Prefer ForecasterDirect

* Horizon-dependent dynamics: The features that predict demand 1 hour ahead (such as immediate recent lags) are often very different from those that predict demand 24 or 168 hours ahead (such as weekly cyclical patterns). A direct model allows each step to learn distinct weights for those inputs.
* Preventing error propagation: Recursive models feed predicted values back as lagged inputs for subsequent steps. Over long horizons, such as 24 to 168 hourly steps, errors can accumulate and distort peak or trough estimates. Direct models rely only on observed historical values for their features.
* Sufficient computational budget: Because `ForecasterDirect` trains one model per step, fitting 24 or 168 separate estimators requires more memory and compute time, though the training process can be accelerated using the `n_jobs` parameter.

## When to Stay with ForecasterRecursive

* Horizon flexibility: `ForecasterRecursive` trains a single estimator and can generate forecasts for any number of steps at prediction time without retraining or specifying the horizon during model creation.
* Computational efficiency: Training a single model is substantially faster and uses far less memory than maintaining dozens or hundreds of step-specific estimators.
* Stable seasonal feature sets: When strong daily and weekly seasonality is properly captured via exogenous calendar features, rolling window transformations, or seasonal lags (such as lag 24 and lag 168), recursive models frequently perform well without severe error drift.

The optimal number of lags for your dataset cannot be determined because no dataset or forecast context has been provided. The best lag structure depends directly on the autocorrelation properties, frequency, and seasonality of your specific time series. In skforecast, you can identify candidate lags using partial autocorrelation analysis and optimize them through backtesting or hyperparameter search.

## Recommended Approaches

* Partial autocorrelation analysis: Use `calculate_lag_autocorrelation` or `pacf` from `skforecast.stats` to inspect which historical time steps show significant correlation with the current value after removing intermediate effects. Lags that exceed the confidence threshold serve as strong initial candidates.
* Hyperparameter tuning: Compare candidate lag sets using `bayesian_search_forecaster`, `grid_search_forecaster`, or `random_search_forecaster` combined with backtesting cross-validation to select the lag set that produces the lowest forecast error.
* Feature selection: Configure an initial forecaster with an extended set of lags and remove non-informative inputs using `select_features`.

## Example: Lag Selection via PACF

```python
import numpy as np
from skforecast.stats import calculate_lag_autocorrelation
from skforecast.recursive import ForecasterRecursive
from sklearn.ensemble import HistGradientBoostingRegressor

# Rank lags by absolute partial autocorrelation
lag_table = calculate_lag_autocorrelation(data=y_train, n_lags=24)

# Keep lags exceeding the asymptotic 95% white-noise threshold
threshold = 1.96 / np.sqrt(len(y_train))
selected_lags = (
    lag_table
    .loc[lag_table["partial_autocorrelation_abs"] > threshold, "lag"]
    .astype(int)
    .sort_values()
    .tolist()
)

# Pass the chosen lags to the forecaster
forecaster = ForecasterRecursive(
    estimator=HistGradientBoostingRegressor(random_state=963),
    lags=selected_lags,
)
```
